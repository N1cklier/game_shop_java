# Структура базы данных игрового магазина

## 1. Назначение

База данных `game_shop.db` предназначена для хранения информации об игроках мобильной игры, доступных игровых предметах, содержимом инвентаря и истории покупок.

Для хранения данных используется SQLite.

## 2. Структура таблиц

### PLAYER — игроки

Хранит информацию об игровых пользователях.

| Поле | Тип данных | Назначение |
|---|---|---|
| player_id | INTEGER | Первичный ключ, идентификатор игрока |
| nickname | VARCHAR(50) | Игровое имя |
| balance | INTEGER | Баланс игровой валюты |

Поле `player_id` формируется автоматически. Поля `nickname` и `balance` обязательны для заполнения. Баланс не может иметь отрицательное значение.

### ITEM — игровые предметы

Содержит перечень предметов, доступных для приобретения во внутриигровом магазине.

| Поле | Тип данных | Назначение |
|---|---|---|
| item_id | INTEGER | Первичный ключ, идентификатор предмета |
| name | VARCHAR(100) | Название предмета |
| price | INTEGER | Стоимость предмета |
| description | VARCHAR(255) | Описание предмета |

Поле `item_id` формируется автоматически. Название и стоимость предмета обязательны для заполнения. Стоимость не может быть отрицательной.

### INVENTORY — инвентарь

Хранит информацию о количестве предметов, принадлежащих игрокам.

| Поле | Тип данных | Назначение |
|---|---|---|
| player_id | INTEGER | Идентификатор игрока, внешний ключ |
| item_id | INTEGER | Идентификатор предмета, внешний ключ |
| quantity | INTEGER | Количество предметов |

Для таблицы используется составной первичный ключ `(player_id, item_id)`, предотвращающий появление нескольких записей одного предмета у одного игрока. Поля `player_id`, `item_id` и `quantity` обязательны для заполнения. Количество предметов должно быть больше нуля.

Внешние ключи связывают записи инвентаря с соответствующими игроками и предметами.

### PURCHASE — история покупок

Предназначена для регистрации совершённых игровых покупок.

| Поле | Тип данных | Назначение |
|---|---|---|
| purchase_id | INTEGER | Первичный ключ, идентификатор покупки |
| player_id | INTEGER | Идентификатор покупателя, внешний ключ |
| item_id | INTEGER | Идентификатор приобретённого предмета, внешний ключ |
| price | INTEGER | Стоимость на момент покупки |
| purchase_date | TEXT | Дата и время покупки |

Поле `purchase_id` формируется автоматически. Все остальные поля обязательны для заполнения. Стоимость покупки не может быть отрицательной.

Внешние ключи обеспечивают связь записи о покупке с существующими игроком и предметом.

## 3. Связи между таблицами

- PLAYER и INVENTORY — связь один ко многим.
- ITEM и INVENTORY — связь один ко многим.
- PLAYER и PURCHASE — связь один ко многим.
- ITEM и PURCHASE — связь один ко многим.

Таблица INVENTORY связывает игроков с игровыми предметами и позволяет хранить их количество. Составной первичный ключ `(player_id, item_id)` обеспечивает уникальность каждой пары «игрок — предмет».

## 4. Использование базы данных

Доступ к базе данных осуществляется через JDBC.

Для взаимодействия с таблицами используются классы репозитория:

- `PlayerRepository` — работа с данными игроков;
- `ItemRepository` — получение информации о предметах;
- `InventoryRepository` — изменение инвентаря;
- `PurchaseRepository` — регистрация покупок.

Обработка покупки выполняется сервисным компонентом `ShopServiceImpl`. Изменение баланса, добавление предмета в инвентарь и запись истории покупки объединены в одну транзакцию SQLite.
